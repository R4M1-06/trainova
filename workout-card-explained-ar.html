٠١ / الفكرة الأساسية

تخيّل البطاقة قالبًا والبيانات محتواها

ملف WorkoutCard.jsx يعرّف مكوّنًا في React؛ أي جزءًا من الواجهة يمكن إعادة استخدامه. وظيفته عرض بطاقة لتمرين واحد. القالب نفسه ثابت، لكن الاسم والوزن والتاريخ تتغيّر حسب البيانات التي تصله.

مثل بطاقة تعريف: التصميم واحد، لكنك تملؤها باسم مختلف لكل شخص. هنا نملؤها ببيانات تمرين مختلف.

أهم نقطة: اسم التمرين لا يأتي من اسم الملف ولا من اسم الدالة. يأتي من الخاصية exercise داخل الكائن workout، ويظهر في السطر <h3>{exercise}</h3>.
  • WorkoutCard: اسم المكوّن في الكود.
  • workout: كائن يحتوي بيانات تمرين واحد.
  • exercise: الخاصية التي تحتوي اسم التمرين، مثل Bench press.

٢. الصفحة الأم تمرّر الكائن إلى البطاقة

في src/pages/WorkoutList.jsx:69:

<div className="grid">{results.map((w) => <WorkoutCard key={w.id} workout={w} />)}</div>
  • results: قائمة التمارين بعد البحث والتصفية والترتيب في الصفحة الأم.
  • .map(): تمرّ على العناصر وتُنتج عنصر واجهة لكل تمرين.
  • w: متغيّر يمثّل كائن التمرين الحالي. اسمه اختياري؛ ليس كلمة محجوزة.
  • workout={w}: أرسل الكائن الموجود في w إلى المكوّن، تحت اسم الخاصية workout.
  • key={w.id}: مفتاح يساعد React على تمييز عناصر القائمة عند تحديثها. ليس عنوانًا ظاهرًا، ولا يصل إلى المكوّن كخاصية عادية باسم key.

٣. المكوّن يستقبل البيانات

export default function WorkoutCard({ workout }) {

البيانات التي يرسلها المكوّن الأب تسمّى props، أي الخصائص المُمرَّرة. كتابة { workout } داخل مُعامل الدالة تستخرج الخاصية workout من كائن الخصائص.

للتوضيح، هذه كتابة بديلة مكافئة لبداية المكوّن، وليست كودًا إضافيًا موجودًا في ملفك:

function WorkoutCard(props) {
  const workout = props.workout;
  // ...
}

٤. نستخرج الاسم من الكائن

const { exercise, date, muscle, weight, sets, e1rm, status } = workout;

هذا الأسلوب اسمه تفكيك الكائن — Object destructuring. بدل كتابة workout.exercise في كل مرة، ننشئ متغيّرًا محليًا اسمه exercise يحمل القيمة نفسها.

// توضيح مكافئ لاستخراج الاسم فقط:
const exercise = workout.exercise;

في مثالنا تصبح قيمة exercise هي "Bench press". هذه ليست عملية بحث أو طلبًا من خادم؛ إنها قراءة خاصية من كائن وصل بالفعل.

٥. نضع الاسم داخل العنوان

<h3>{exercise}</h3>

الوسم h3 عنوان. الأقواس { } هنا تعني: «قيّم تعبير JavaScript الموجود داخلها وضع نتيجته في الواجهة». لذلك يقرأ React قيمة المتغيّر ويعرض الاسم. النتيجة المكافئة في HTML:

<h3>Bench press</h3>
بدون الأقواس، كتابة <h3>exercise</h3> تعرض كلمة exercise حرفيًا، وليس قيمة المتغيّر.
٠٣ / الملف كاملًا

الكود الأصلي الذي قرأته

المصدر: C:\Users\memah\trainova\trainova\src\components\WorkoutCard.jsx — الأسطر ١–١٤.

export default function WorkoutCard({ workout }) {
  const { exercise, date, muscle, weight, sets, e1rm, status } = workout;
  return (
    <article className="card workout">
      <div className="workout-top">
        <h3>{exercise}</h3>
        <span className={`badge ${status}`}>{status}</span>
      </div>
      <p className="muted">{date} · {muscle}</p>
      <p>{weight} kg × {sets.join(" / ")} reps</p>
      <p className="muted">Estimated 1RM: <strong>{e1rm} kg</strong></p>
    </article>
  );
}

هذا JSX: صيغة تشبه HTML داخل JavaScript يستخدمها React لوصف الواجهة. الملف يحتاج بيئة التطبيق لتحويل JSX وتشغيله؛ أما صفحة الشرح هذه فهي HTML مستقل يفتح مباشرة.

٠٤ / فهم بقية الملف

كل جزء له وظيفة محدّدة

السطر ١: تعريف المكوّن وتصديره

function تعرّف دالة، وWorkoutCard اسمها. نبدأ أسماء مكوّنات React بحرف كبير حتى تُعامل كمكوّنات عند استخدامها في JSX. عبارة export default تتيح استيراد المكوّن في ملف آخر؛ وصفحة WorkoutList.jsx تستورده بالفعل في السطر ٣.

السطران ٣ و٤: إرجاع الواجهة والحاوية

return (...) يعيد وصف الواجهة. الأقواس العادية تجمع JSX المكتوب على عدة أسطر. العنصر article هو الحاوية الخارجية للبطاقة.

<article className="card workout">

className هو اسم الخاصية المستخدمة هنا لإضافة أصناف CSS. القيمة تحتوي صنفين منفصلين: card وworkout. هذه أسماء للتنسيق، ولا تُستخرج منها بيانات التمرين. وجود كلمة workout في النص لا يربط الصنف تلقائيًا بالكائن الذي يحمل الاسم نفسه.

الأسطر ٥–٨: مجموعة العنوان وشارة الحالة

div يجمع العنوان والشارة. الصنف workout-top يوفّر نقطة للتنسيق في CSS؛ هذا الملف وحده لا يحدّد اللون أو ترتيب العناصر بصريًا.

<span className={`badge ${status}`}>{status}</span>

تُستخدم status مرتين:

  1. داخل className لإنتاج اسم صنف متغيّر. النص بين علامتَي backtick يسمى Template literal، و${status} يدرج القيمة فيه.
  2. بين وسمَي span لعرض الحالة كنص للمستخدم.

عندما تكون الحالة "progress"، تكون النتيجة:

<span class="badge progress">progress</span>

إذًا badge صنف ثابت، وprogress صنف يعتمد على البيانات. اللون الفعلي تحدّده قواعد CSS خارج هذا الملف.

السطر ٩: التاريخ والعضلة

<p className="muted">{date} · {muscle}</p>

فقرة تعرض التاريخ، ثم الرمز الثابت ·، ثم اسم مجموعة العضلات. في المثال تظهر 2026-10-05 · Chest. لا يوجد هنا تحويل للتاريخ أو ترجمة لاسم العضلة. وmuted اسم صنف CSS، وليس أمرًا في JavaScript.

السطر ١٠: الوزن وتكرارات المجموعات

<p>{weight} kg × {sets.join(" / ")} reps</p>

weight هو الوزن، وsets مصفوفة تحتوي عدد التكرارات لكل مجموعة. الدالة join(" / ") تجمع عناصر المصفوفة في نص واحد وتضع / بينها.

[8, 8, 7].join(" / ")
// "8 / 8 / 7"

المعنى: المجموعة الأولى ٨ تكرارات، الثانية ٨، والثالثة ٧. النتيجة المعروضة:

60 kg × 8 / 8 / 7 reps
رمز × هنا نص للعرض فقط؛ الكود لا ينفّذ عملية ضرب. وكذلك kg وreps نصّان ثابتان.

السطر ١١: أقصى وزن تقديري لتكرار واحد

<p className="muted">Estimated 1RM: <strong>{e1rm} kg</strong></p>

1RM يعني أقصى وزن لتكرار واحد، وe1rm قيمة تقديرية له. المكوّن يعرض القيمة التي استلمها، ولا يحسبها. ملف البيانات يحتوي تعليقًا يذكر معادلة Epley، لكن لا توجد معادلة حساب داخل هذه البطاقة.

strong يعطي القيمة أهمية دلالية، وتظهر عادة بخط عريض. القيمة العددية 76.0 تظهر هنا 76؛ لا يوجد toFixed() لفرض منزلة عشرية.

الأسطر ١٢–١٤: إغلاق البنية

</article> يغلق البطاقة، و); ينهي عبارة الإرجاع، والقوس الأخير } يغلق الدالة.

٠٧ / نقاط قد تسبّب الالتباس

أسئلة وإجابات سريعة

هل القوسان { } لهما المعنى نفسه في كل مكان؟

لا. في WorkoutCard({ workout }) وفي const { exercise } = workout نستخدمهما لتفكيك الكائن. أما بين وسوم JSX، مثل {exercise}، فهما يفتحان مكانًا لتعبير JavaScript. السياق هو الذي يحدّد المعنى.

هل {exercise} هو نفسه ${status}؟

الهدف متشابه: إدراج قيمة، لكن السياق مختلف. {exercise} تعبير داخل JSX. و${status} إدراج داخل نص JavaScript محاط بعلامتَي backtick؛ وهذا النص كله موجود داخل تعبير JSX الخاص بـ className.

ماذا لو لم تصل البيانات الصحيحة؟
  • إذا كان workout هو undefined أو null، يفشل تفكيكه في السطر ٢.
  • إذا كانت exercise غير موجودة، تكون قيمتها undefined، ولا يظهر نص للاسم داخل العنوان.
  • إذا كانت sets مفقودة أو لا تدعم join()، يفشل استدعاء sets.join().

الملف لا يحتوي قيمًا افتراضية أو تحققًا من البيانات. هذه ملاحظة عن افتراضاته، وليست إشارة إلى وقوع خطأ في البيانات الحالية.

هل البطاقة تحفظ أو تجلب أو تعدّل التمارين؟

لا. لا يوجد داخلها طلب شبكة أو حفظ أو حالة محلية أو زر تعديل. تستقبل البيانات وتصف طريقة عرضها. عندما يعيد React تصييرها ببيانات جديدة، تستخدم تلك البيانات في الواجهة الجديدة.

أين أغيّر الاسم فعلًا في المشروع؟

في المسار الحالي، الأسماء تأتي من src/data/mockWorkouts.js. لتغيير اسم سجل معيّن، تغيّر قيمة exercise في ذلك السجل. لا تحتاج لتغيير اسم الدالة WorkoutCard أو اسم الملف. لم أعدّل أيًّا منهما.
